## Тема «Nothing OS × iOS» (2026-11-11, ветка v0.3-monitoring)

Тема `nothing` переработана и стала темой по умолчанию (`settings.json["theme"]`); «SIRIUS — голография» и «iPhone»
остаются в Настройки → Интерфейс. Меняется только оформление: функции, сигналы и логика прежние.

- Навигация: значки панелей (CHAT, CODE, SYSTEM, TERMINAL, LOGS, HISTORY), «Скрыть», «Сброс» и «Настройки» —

  выделение и наведение плавные. Кнопки в верхней полосе в этой теме скрыты, но существуют и работают.
- Чат: сообщение пользователя — светлая карточка, LISA — тёмная с тонким контуром; поле ввода — капсула, белая кнопка отправки.
- Типографика: Inter 4.1 (лежит в `resources/fonts`, лицензия OFL; подключается при запуске только для SIRIUS), моноширинный шрифт для показателей,
  заголовков панелей и строки состояния; точечный шрифт 5×7 (`interface/dotmatrix.py`) — логотип SIRIUS и таймер Pomodoro.
- Островок: монохромная капсула, сетка точек в раскрытой части, визуализатор из точек; расположение элементов не менялось.
- Переходы (`interface/motion.py`, во всех темах): панель плавно проявляется при открытии, вкладки настроек и SYSTEM — при переключении.
- Тесты: `tests/test_theme.py` (18).

## Островок — Living Island (2026-11-10, ветка v0.3-monitoring)

Компактная полоска (`interface/compact_bar.py`) развита в интерактивную капсулу. Это то же окно: прежние сигналы,
методы и поведение компактного режима сохранены, второго окна нет.

### Капсула и состояния
- Состояния COMPACT, EXPANDED, MEDIA, NOTIFICATION, SYSTEM, VOLUME, BRIGHTNESS, BATTERY, INTERACTIVE (`island/states.py`).
- Единый диспетчер `interface/island/state_manager.py`: основа (открыта пользователем) и временное событие поверх неё;
  приоритеты событий, закрепление, сворачивание после бездействия, пауза таймеров под курсором.
- Анимации (`interface/island/animator.py`): размер окна, скругление, прозрачность содержимого. Скорость настраивается, можно отключить.
- Окно всегда по размеру капсулы, фокус у других окон не отбирает, после перетаскивания запоминает место,
  возвращается на место при смене разрешения и набора мониторов. У нижнего края раскрывается вверх.
- Строка капсулы не переполняется: при нехватке места метрики сокращаются, второстепенное скрывается.

### Режимы
- **Медиа** (`monitoring/winrt_bridge.py`): название, исполнитель, обложка, плеер, прогресс, play/pause, следующий и
  предыдущий трек, перемотка. Windows GSMTC, по событиям, для любого совместимого плеера.
- **Визуализатор**: три вида по настоящему пиковому уровню звука устройства вывода (`monitoring/win_audio.py`).
  Это уровень сигнала, а не спектр частот.
- **Система**: CPU, GPU, RAM, VRAM, температуры, сеть, аккумулятор — из существующего MonitorService; Wi-Fi, Bluetooth,
  Caps Lock и Num Lock — `monitoring/win_system.py`.
- **Индикаторы событий**: громкость, яркость (встроенный экран ноутбука), Caps Lock и Num Lock, подключение питания.
  Опрос раз в 0,3 с, только пока островок на экране.
- **Уведомления** (`island/notifications.py`): очередь, приоритет, объединение повторов, защита от спама, журнал.
  Предупреждения мониторинга идут в островок вместо трея, когда он на экране. Уведомления Windows — по желанию
  (выключены по умолчанию), список запрашивается раз в 3 с.
- **Инструменты**: файловая полка (файлы с диска не перемещаются и не удаляются, перетаскивание наружу только копирует),
  история буфера обмена (поиск, повторное копирование; пароли, токены и ключи не сохраняются без разрешения),
  Pomodoro (идёт без островка, переживает перезапуск), быстрые действия (встроенные и свои: файл, папка, приложение, сайт).
- **LISA**: кайма капсулы по состоянию, раскрытие ответа при вопросе из островка, сообщения «ответ готов», «ошибка», «офлайн».

### Настройки и хранение
- Вкладка «Островок» в окне настроек; значения в `settings.json["island"]`, проверка — `island/settings.normalize`.
  Старые настройки без этого раздела загружаются как раньше.
- Полка, состояние Pomodoro и (если включено) история буфера — `storage/island.json`.
- По умолчанию островок виден только в компактном режиме; «показывать всегда» включается в настройках.

### Зависимости
- Пакеты `winrt-*` (PyWinRT) — для медиа и уведомлений Windows. Необязательные: без них остальной островок работает.

### Ограничения
- Состояние «LISA слушает микрофон» появится вместе с распознаванием речи (v0.6): микрофона в SIRIUS пока нет.
- Имя сети Wi-Fi Windows 11 может не отдать без доступа к геолокации — тогда показано только «подключён».

### Тесты
- `tests/test_island.py` — 48 тестов: логика, диспетчер состояний, окно, контроллер, связь с главным окном.
  Системные сервисы Windows в тестах выключены (`IslandController.SYSTEM_SERVICES`).

## v0.3 — Мониторинг (2026-11-07, ветка v0.3-monitoring)

### Мониторинг
- **Постоянный сбор данных** раз в 2 с (`interface/monitor_service.py`): нужен графикам, предупреждениям, компактному режиму и ответам LISA. Без процессов снимок занимает ~60 мс; список процессов (~0,7 с) собирается раз в 4 с и только пока открыта панель SYSTEM.
- **Новые данные** (`monitoring/system_info.py`): загрузка по ядрам, диски (место, скорость чтения и записи), сеть (приём и отправка), батарея и питание, самые тяжёлые процессы.
- **История за 5 минут** только в памяти (`monitoring/history.py`), без баз данных.
- **Температуры**: видеокарта — через nvidia-smi. Процессор — «Unavailable»: Windows не отдаёт этот датчик без прав администратора, а повышать права SIRIUS не будет.

### Панель SYSTEM — вкладки
- **Обзор**: CPU, RAM, GPU, VRAM, температуры, питание, Ollama, модель с её видеопамятью, скорость последнего ответа, голос.
- **Графики**: CPU, GPU, RAM, VRAM за 5 минут, загрузка каждого ядра.
- **Процессы**: самые тяжёлые по CPU и памяти — только просмотр, без завершения.
- **Диски и сеть**: место на дисках, скорость дисков, графики сети.
- **Сессия**: время работы, ответы и токены, средняя скорость модели и время до первого токена, пики нагрузки и температур, число предупреждений.

### Ресурсы Ollama
- Скорость генерации (токены в секунду) и время до первого токена по данным Ollama (`eval_count`, `eval_duration`).

### Предупреждения (`monitoring/alerts.py`)
- Видеопамять, оперативная память, CPU (15 с подряд), температура GPU и CPU, место на диске C:, заряд батареи. Пороги — в «Настройки → Мониторинг».
- Повтор не чаще раза в 5 минут и только после того, как значение опустилось ниже порога.
- Показ в строке состояния и индикаторе панели SYSTEM; в трее — когда окно скрыто или включён компактный режим; голосом LISA — только если включено в настройках и голос включён.

### LISA и мониторинг
- Вопрос о компьютере («как там компьютер?», «почему греется?», «сколько места на диске?») дополняется реальными данными мониторинга (`monitoring/system_report.py`). Недоступные датчики названы явно, чтобы модель их не выдумывала. Только чтение.
- Свечение LISA меняется по состоянию системы: янтарное при высокой нагрузке, красное и быстрее пульсирует при перегреве.

### Режимы и удобство
- **Компактный режим** (`interface/compact_bar.py`, Ctrl+M): полоска у верхнего края экрана поверх окон — мини-LISA, ввод, последняя фраза ответа, мини-метрики, голос, возврат в полное окно (Esc, Ctrl+M или ⤢). Полоску можно перетаскивать.
- **Освободить ресурсы** (Ctrl+Shift+H): Qwen и голос выгружаются из памяти — для игр и тяжёлых задач. «Вернуть» загружает их снова; новое сообщение тоже загрузит модель.
- **Значок в трее**: показать окно, компактный режим, освободить ресурсы, выход. По желанию закрытие окна сворачивает SIRIUS в трей (выключено по умолчанию: при закрытии модель выгружается).
- **Горячие клавиши**: Ctrl+1…6 — панели, Ctrl+M — компактный режим, Ctrl+Shift+V — голос, Ctrl+Shift+H — ресурсы, Ctrl+, — настройки, Esc — остановить речь. Список — в подсказке кнопки «Настройки».
- **Автозапуск с Windows** (`core/autostart.py`): запись только в HKCU\…\Run текущего пользователя, без прав администратора. Выключен по умолчанию.

### Код
- Возможности окна v0.3 вынесены в `interface/window_v03.py` (примесь к MainWindow), графики — `interface/charts.py`.
- Новые тесты: `tests/test_monitoring_v03.py`.


## v0.2.6 — экран запуска и модель в памяти (2026-11-07)
- **Экран запуска** (`interface/boot_overlay.py`): вращающиеся голографические кольца, общий прогресс и этапы — подключение к Ollama, проверка модели, загрузка Qwen в видеопамять, голосовой модуль. Щелчок или Esc скрывают экран, загрузка продолжается в фоне. При ошибке экран показывает, что недоступно, и исчезает.
- **Qwen загружается в видеопамять при запуске** (`ModelManager.preload`, `interface/workers.BootWorker`): первый ответ начинается сразу (проверено: загрузка 3,1 с при старте, первый токен через 0,26 с). Прогрев использует тот же `num_ctx`, что и чат, иначе Ollama перезагрузила бы модель.
- **При закрытии модель выгружается** (`ModelManager.unload`, keep_alive = 0): видеопамять освобождается сразу. Пока SIRIUS открыт, модель держится в памяти (keep_alive 30 мин, продлевается каждым запросом); после аварийного завершения Ollama сама освободит память через 30 минут.
- При смене модели или адреса в настройках прежняя модель выгружается в фоне.
- Голос (Silero или Piper) тоже загружается при запуске, если включён VOICE.
- Тесты окна не загружают настоящую модель (заглушка в `tests/conftest.py`).

## v0.2.3 — нежный голос и понятная речь (2026-11-07)

### Исправлено: «абракадабра» вместо слов
Причин было три, все проверены на реальных ответах Qwen:
- **Латинские слова** (Python, Ollama, GPU, имена функций) Piper отдавал русскому голосу английскими звуками (θ, ɹ, əʊ…), которых модель не знает, — получались непонятные слова. Теперь латиница записывается кириллицей: словарь частых слов и имён (пайтон, оллама, сириус, лиза), аббревиатуры по буквам (джи-пи-ю), идентификаторы по частям (`stream_reply` → «стрим риплай»), остальное — по правилам чтения. На реальных ответах фраз с английскими звуками: было 5 из 8, стало 0 из 8.
- **Нарезка потока** рвала фразу внутри чисел и сокращений («Python 3.» | «12 вышла, т.» | «е. …»). Теперь фраза завершается, только когда после точки пришёл пробел, а точка после одной буквы или сокращения (т. е., г., руб.) фразу не завершает.
- **Код читался вслух**, если блок приходил по частям. Теперь всё между ``` пропускается. Если ответ — только код, LISA говорит «Код показан на экране».
- Раскрываются сокращения (т.е., т.к., и т.д., г., руб., тыс.), проценты и градусы согласуются с числом (3 процента, 52 градуса), «1 500» читается как число, ссылки и пути — «ссылка» и «путь к файлу», номера пунктов списков, заголовки и разделители не озвучиваются, длинные фразы делятся по запятым.

### Изменено: голос мягче и нежнее
- Голос Piper ru_RU-irina (единственный женский русский голос Piper) обрабатывается после синтеза (`voice/audio_effects.py`): высота +4% без изменения темпа, смягчение резких высоких звуков, плавные края фраз, короткая пауза между фразами.
- Интонация живее: параметры Piper ближе к значениям модели (noise_scale 0.6, noise_w 0.75 вместо 0.5 и 0.7).
- Скорость по умолчанию 1.0 вместо 1.2. Если в настройках осталось прежнее значение по умолчанию 1.2, оно заменяется на 1.0; выбранная вами скорость сохраняется.
- В настройках («Голос»): «Высота голоса», «Мягкость», кнопки «Нежный голос» и «Исходный голос». Тестовая фраза содержит латинские имена — сразу слышно произношение.

### Зависимости
- `numpy` указан явно (уже ставился вместе с piper-tts).

### Ограничения
- Ударения расставляет espeak-ng (часть Piper): в редких словах ударение может быть неверным.
- Лучшее качество дала бы другая модель речи (например, Silero с голосами xenia/baya), но это смена технологии (нужен PyTorch, около 1 ГБ) — только по согласованию.

## v0.2.1 — новый облик LISA (2026-11-07)

По изображению, которое прислал пользователь.

### Изменено
- **LISA.** Голографическая девушка с референса вместо векторного силуэта (`resources/images/lisa.png`). Изображение подготовлено скриптом `tools/prepare_lisa_avatar.py`: фигура вырезана по контуру, тёмный фон прозрачный, сама фигура полупрозрачная, как голограмма. Поверх изображения рисуются свечение, световой луч от подставки, орбиты с движущимися точками, линии развёртки и сканирующий луч по фигуре, свечение подставки. Во время речи — свечение губ и звуковые полосы. Цвет зависит от состояния: THINKING — фиолетовый, ERROR — красный, STOPPED и OFFLINE — приглушённые. Если файла нет, рисуется прежний векторный силуэт.
- **Фон.** Ночной город на всё окно: высотки с горящими окнами, неоновые полосы, боке, фиолетовое свечение у горизонта, тёмный стол внизу. Рисуется программно (чётко на любом разрешении), строится один раз для размера окна (12–32 мс).
- **Прозрачные окна.** Панели — стекло: сквозь них виден город, но не содержимое других панелей. Поля ввода, списки, консоль и панель управления тоже прозрачные.

### Производительность
- Свечение, луч и подставка аватара готовятся один раз, в кадре только копируются: кадр анимации занимает 0,5–1,5 мс вместо 50 мс у первой версии нового аватара.

### Ограничения
- Исходное изображение маленькое (фигура 360×627 пикселей), поэтому на больших экранах LISA немного мягче, чем интерфейс. С исходником в высоком разрешении аватар пересобирается командой `python tools/prepare_lisa_avatar.py <картинка>`.
- Лицо на изображении статичное: глаза не моргают, губы не двигаются. Речь показывается свечением губ и полосами.

## v0.2 — LISA Workspace (2026-11-07)

### Добавлено
- **Рабочее пространство.** LISA в центре, вокруг шесть плавающих панелей: CHAT, CODE, SYSTEM, TERMINAL, LOGS, HISTORY. Панели — дочерние виджеты одного окна, а не отдельные окна Windows. Их можно перетаскивать за заголовок, менять размер за края и углы, сворачивать до заголовка (кнопкой или двойным кликом) и закрывать. Активная панель поднимается наверх. Ни одна панель не может уйти за границы окна.
- **Панель управления.** Название, статус Ollama, переключатели шести панелей (повторное нажатие не создаёт копию), «Скрыть все», «Сброс» (стандартная компоновка), VOICE, Настройки.
- **Стандартная компоновка.** CHAT справа, SYSTEM сверху слева. Остальные панели открываются по кнопке. При изменении размера окна панели держатся ближайших краёв, а их размеры восстанавливаются, когда окно снова становится больше.
- **Сохранение компоновки.** Координаты, размеры, видимость, свёрнутость, порядок наложения, активная панель и компоновка хранятся в `settings.json` (ключ `workspace`). Компоновка записывается через 1,5 с после изменения и при закрытии окна. Координаты за пределами экрана исправляются, повреждённое значение заменяется стандартной компоновкой.
- **CODE.** Блоки кода из реальных ответов LISA в текущем диалоге: язык, подсветка (Pygments), выбор блока, выделение, копирование. Если кода нет — «No code generated». Код никогда не выполняется.
- **SYSTEM.** CPU, RAM (всего, занято, свободно), загрузка, видеопамять и температура GPU (nvidia-smi), статус Ollama, модель в видеопамяти (`/api/ps`), состояние Piper. Опрос раз в 1,5 с в фоновом потоке и только пока панель открыта. Недоступные датчики показываются как «Unavailable».
- **LOGS.** Журнал `logs/sirius.log` в реальном времени: читаются только новые строки, при открытии — только хвост файла. Есть фильтр INFO/WARNING/ERROR, поиск, пауза, автопрокрутка и очистка отображения (файл не изменяется).
- **TERMINAL.** Ограниченная консоль для команд, которые пользователь вводит сам. Работает через QProcess, без оболочки. Показывает код возврата и время, поддерживает историю (стрелки, `history`), `cd`, `clear` и кнопку «Стоп», которая завершает и дочерние процессы. Повышение прав и закодированные команды PowerShell запрещены. Удаление, перемещение, реестр, службы и выключение требуют подтверждения. Если SIRIUS запущен от администратора, консоль отключена. Модель к консоли доступа не имеет.
- **HISTORY.** Отдельная панель с поиском по названию.
- **Аватар.** Новое состояние OFFLINE (Ollama недоступна). Приоритет состояний: ERROR > SPEAKING > THINKING > OFFLINE > STOPPED > IDLE. Тихая проверка Ollama раз в 10 с без диалогов.
- **CHAT.** Индикатор подключения к модели в заголовке, анимированный индикатор генерации, кнопка «+ Новый».
- Тёмный системный заголовок окна (DWM).
- Тесты: панели, компоновка, сохранение, CODE, HISTORY, SYSTEM, LOGS, TERMINAL, состояния аватара. Всего 222 теста.

### Изменено
- Системная инструкция LISA: любой код оформляется блоком Markdown с указанием языка. Без этого модель иногда отдавала код простым текстом, и CODE его не видела.
- Аватар: частота кадров зависит от состояния (IDLE — 20 кадров/с, OFFLINE — около 8, речь и размышление — 30), в свёрнутом окне перерисовки нет. Свечение и кольцо THINKING больше не обрезаются краями виджета.
- Минимальный размер окна — 900×520. Сохранённый размер окна ограничивается доступной областью экрана.
- «Восстановить интерфейс» в настройках также сбрасывает расположение панелей.

### Исправлено
- Сохранение окна настроек больше не может затереть свежее расположение панелей старой копией настроек.

### Известные ограничения
- На этой машине каждый запрос к `http://localhost:11434` теряет около 2 с (Windows сначала пробует IPv6), а `http://127.0.0.1:11434` отвечает за 13 мс. Проблема была и в v0.1.1. Решение — указать адрес `http://127.0.0.1:11434` в настройках.
- TERMINAL не поддерживает интерактивные программы (ввод закрыт). Встроенные команды cmd запускаются через `cmd /c`. Проверка опасных команд — это защита от ошибок пользователя, а не изоляция: например, `python -c "..."` она не анализирует.
- Полупрозрачность панелей показывает фон рабочей области, но не аватар и не другие панели: настоящее размытие в QWidget слишком дорогое.
- Ручная проверка перетаскивания мышью на реальном экране за пользователем. Автоматически проверены перетаскивание и изменение размера через QTest, отрисовка при 1280, 1366, 1920 и 2560 и запуск окна на платформе Windows.

## v0.1.1 — стабильность (2026-11-07)

### Исправлено
- **Ответы модели.** Системная инструкция переписана: LISA отвечает сразу по существу, без приветствий и самопредставления, не повторяет вопрос и честно сообщает, если данных недостаточно. Проверено на реальной модели: столица Италии, 25 × 4, объяснение Python, простой код на Python.
- **Голос (Piper).** Смена пути к голосовой модели больше не сбрасывает загруженную модель, если путь не изменился (сохранение настроек, отмена окна настроек, тест голоса). GUI-поток не ждёт синтеза: проверено, ожидание сократилось с 0.38 с до 0 с. Следующая фраза после такого сброса больше не ждёт перезагрузки модели (2.4 с → 0.09 с).
- **Остановка речи.** Фразы, созданные до остановки, не воспроизводятся. Запоздавший сигнал от уже доигранного файла не пропускает текущую фразу. Временный WAV, который ещё занят плеером, не вызывает ошибку: удаление повторяется позже.
- **Остановка генерации.** Клик «Стоп» закрывает HTTP-поток, и чтение прекращается сразу после получения ответа модели (проверено: 0.05–0.09 с). Прерванный ответ не сохраняется в диалог, речь по нему останавливается.
- **Закрытие окна.** Порядок: генерация → голос → загрузка модели → проверка Ollama → название диалога. Все фоновые задачи дожидаются завершения. Ожидание запуска сервера Ollama прерывается.

### Добавлено
- Тесты на исправленные проблемы: голос (смена пути, блокировки, стоп, запоздавшие сигналы), остановка генерации, поведение окна, импорт всех модулей, реальные ответы модели.
- Git-репозиторий и правила `.gitignore` для `.venv`, логов, временных WAV, истории чатов и пользовательских настроек.
- Этот журнал.

### Известные ограничения
- До первого фрагмента ответа остановка ждёт ответа сервера Ollama: обычно 1–2 с.
- Модель `qwen3:8b-q4_K_M` занимает около 6 ГБ видеопамяти, часть вычислений идёт на CPU. Требование 4–5 ГБ не выполнено.
- Модель иногда выдумывает факты о массовой культуре.
